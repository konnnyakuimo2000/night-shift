# NIGHT//SHIFT — エンディング（案）

最終更新: 2026-10-04 ／ 状態: **検討中**

DAY30（最終夜）の後、**30日間の記録**と**最終夜の結果**でエンディングが決まる。
舞台は 1990年代末のブラック企業。「会社にとっての良い結末」と「主人公にとっての良い結末」は一致しない。

---

## 1. 判定に使う記録

| 記録 | 内容 | 記録する場所 |
|---|---|---|
| **最終夜の結果** | DAY30 の自律型攻撃AIの本命攻撃を 完全防衛 ／ 一部被害 ／ 重大インシデント | DAY30 の評価 |
| **重大な見逃し** | 30日間で悪意ある接続を許可した件数の合計（研修を除く） | 各夜の評価 |
| **平均ランク** | DAY8〜30 の総合評価の平均（S/A/B/C/D） | 各夜の評価 |
| **自分のアカウントの被害** | T4（運用担当者アカウントの不正利用）を許した回数 | 脅威の記録 |
| **AIへの依存度** | サイバー防御AIが処理した件数 ÷ DAY25 以降の全件数 | SOC-AI の記録 |
| **残業回数** | 缶コーヒーで残業した夜の数 | 所持品の記録 |
| **労務の証拠**（0〜5） | 隠し要素。ブラック企業の違法行為の証拠を集めた数（下記 §3） | 新規 |
| **前任者の手がかり**（0〜4） | 隠し要素。自律型攻撃AIを作った人物の手がかり（下記 §4） | 新規 |
| **正しい報告** | 報告（エスカレーション）を正しく行った件数（T5, T8 など） | 各夜の評価 |

## 2. エンディング一覧

上から順に判定し、**最初に条件を満たしたもの**になる。

| # | 名前 | 種類 | 条件 | 内容 |
|---|---|---|---|---|
| E1 | **踏み台** | BAD | 最終夜に**自分のIDで侵入された**、または自分のアカウントの被害が 2回以上 | 攻撃が主人公のアカウントから行われていた。会社は主人公を「犯人」として警察に突き出す。**パスワードを付箋に書いていた**場合は、その付箋が証拠として押収される（研修のパスワード記録を回収） |
| E2 | **全責任** | BAD | 最終夜が**重大インシデント**、または重大な見逃しが 5件以上 | 顧客情報の流出／ランサムウェアで業務停止。会社は「夜間担当の過失」と発表し、主人公は懲戒解雇。さらに**損害賠償の請求書**が届く（金額は所持金の全額） |
| E3 | **真夜中の答え合わせ** | TRUE | 最終夜が**完全防衛**、平均ランク A 以上、**前任者の手がかり 4つ**、労務の証拠 3つ以上 | 自律型攻撃AIを作ったのは、この会社に使い潰されて辞めた**前任の夜勤担当者**だった。主人公は最終夜に攻撃元を突き止め、前任者と（チャットで）対話する。最後に「通報する／証拠を労基署に持っていく」を選ぶ（どちらを選んでもエンディングの文章が変わる） |
| E4 | **労基署へ** | GOOD | 最終夜が**完全防衛か一部被害**、**労務の証拠 5つ** | 集めた証拠を持って労働基準監督署へ。会社に是正勧告、未払いの深夜割増・罰金の返還（**30日間の罰金の合計が戻ってくる**演出）。主人公は会社を辞めて新しい生活へ |
| E5 | **引き抜き** | GOOD | 最終夜が**完全防衛**、平均ランク A 以上、正しい報告 5件以上 | 最終夜の対応の記録が業界で噂になり、外資系のセキュリティ会社から誘いが来る。ブラック企業を辞めて転職 |
| E6 | **正社員登用（という名の…）** | NORMAL+ | 最終夜が**完全防衛**、平均ランク B 以上 | 会社から正社員登用の通知。ただし「管理職扱いのため残業代なし」「夜勤は引き続き担当」。給与明細の額はほぼ同じ。会社にとっては最高の結末 |
| E7 | **AIに席を奪われる** | NORMAL | 最終夜が**完全防衛か一部被害**、AIへの依存度 50% 以上 | 「AIがあれば君はいらない」。会社は SOC-AI の月額契約に切り替え、主人公の契約は終了。最後の夜に AI が丁寧なお別れの挨拶をくれる |
| E8 | **朝日がまぶしい** | NORMAL | 残業回数 10回以上、平均ランク C 以下 | 働きすぎて体を壊し、退職。帰りの電車で見た朝日がやけにまぶしい |
| E9 | **契約更新** | NORMAL | 上のどれにも当てはまらない | 「来月もよろしく」。翌月のシフト表が届く。何も変わらない夜がまた始まる |

### 途中終了（契約打ち切り）
- 週の最後の「週間評価」で**2週続けて最低ランク（D）**だと、契約打ち切りで途中終了（DAY14・DAY21 の終わりに判定）。
- 途中終了はエンディング一覧に「**E0 試用期間満了**」として記録される。その週の初日からやり直せる。

## 3. 隠し要素: 労務の証拠（0〜5）

普段の業務の中に、ブラック企業の違法行為の証拠が紛れている。見つけた資料は**担当者用ワークステーションの「個人フォルダ」に保存**すると1つ数えられる（保存しないと数えない）。

| # | 証拠 | 見つけ方（例） | 解放日 |
|---|---|---|---|
| 1 | **給与明細**（深夜割増なし） | 給与明細メールを個人フォルダに保存 | DAY8〜 |
| 2 | **罰金の社内規程**（「業務改善協力金」） | 社内規程の文書の、最後のページの小さな注記 | DAY10〜 |
| 3 | **勤務記録の改ざん** | ログ解析で、勤務管理サーバーの「タイムカード修正」記録を見つける | DAY15〜（サーバー運用管理） |
| 4 | **上長の指示メール**（「深夜手当は日当に含めると説明しろ」） | 誤送信メールとして1日だけ届く。翌日には削除される | DAY19 |
| 5 | **前任者の退職理由**（過労） | ユーザー管理で、前任者の無効化されたアカウントのメモ欄 | DAY19〜（ユーザー管理） |

- 証拠を集めるのは**業務時間内**（そのぶん業務の手が止まる）。
- 個人フォルダはサブモニター（ワークステーション）にある → **サブモニターが無いと集められない**。

## 4. 隠し要素: 前任者の手がかり（0〜4）

自律型攻撃AIを作ったのは、前任の夜勤担当者。30日間で少しずつ手がかりが見える。

| # | 手がかり | 見つけ方（例） | 解放日 |
|---|---|---|---|
| 1 | 前任者の**付箋**（ワークステーションの裏に残っていた） | 研修で付箋を使った人ほど気付きやすい演出 | DAY8〜 |
| 2 | 退職者アカウントの悪用（T6）の**接続元**が、ある IP の範囲 | T6 の要求をログ解析で調べる | DAY12〜 |
| 3 | 攻撃支援AIのフィッシングメールに、**社内の人しか知らない言い回し** | T5／AIフィッシングのメール本文 | DAY26〜 |
| 4 | 自律型攻撃AIの通信元が、手がかり2と**同じ IP の範囲** | 相関タイムライン、または最終夜のログ | DAY28〜 |

- 4つ揃えると、DAY30 の最終夜に**「攻撃元を追跡する」**という選択肢が出る（TRUE エンドの条件）。

## 5. エンディング画面

1. **社内報／新聞記事風の1枚絵**（日付付き。1999年の朝刊・社内報のレイアウト）。
2. **30日間の成績表**: 平均ランク、処理件数、重大な見逃し、所持金、罰金の合計、残業回数、購入した機材・ツール。
3. **エピローグの一文**（所持品・記録で変わる。例: 「サブモニターは次の夜勤担当に払い下げられた」「パスワードの付箋はまだ机に貼ってある」）。
4. **エンディング一覧**（E0〜E9。見たものだけ名前が出る。未取得は「？？？」）。
5. タイトル画面へ戻る。2周目以降、タイトルに「エンディング一覧」が出る。

## 6. 実装メモ
- 30日間の記録を保存する `CareerRecord`（新規）: 各夜の評価・ランク・罰金・残業・AI処理件数・T4 の結果・証拠・手がかり。
- 判定は `EndingResolver`（新規）。上の表を上から順に評価する。条件の数値は ScriptableObject（`EndingDefinition`）で調整できるようにする。
- 研修のパスワード記録（`OperatorAccount`）は E1 の演出に使う。
