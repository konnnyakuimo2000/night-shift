# NIGHT//SHIFT — エンディング・ゲームオーバー（案）

最終更新: 2026-10-04 ／ 状態: **検討中**

- **本編エンド: 6種類**。DAY30（最終夜）の後、**最終夜の結果**と**30日間の記録**で決まる。
- **ゲームオーバー**: DAY8〜29 の途中で、決まった条件を満たすとその場で終了する（§3）。
- **サブエンド**: 後で追加する（今回は扱わない）。

舞台は 1990年代末のブラック企業。「会社にとっての良い結末」と「主人公にとっての良い結末」は一致しない。

---

## 1. 判定に使う記録

| 記録 | 内容 | 使う場所 |
|---|---|---|
| **最終夜の結果** | DAY30 の自律型攻撃AIの本命攻撃を 完全防衛 ／ 一部被害 ／ 重大インシデント | 本編エンド |
| **平均ランク** | DAY8〜30 の総合評価の平均（S/A/B/C/D） | 本編エンド |
| **正しい報告** | 報告（エスカレーション）を正しく行った件数（T5, T8 など） | 本編エンド |
| **AIへの依存度** | サイバー防御AIが処理した件数 ÷ DAY25 以降の全件数 | 本編エンド |
| **前任者の手がかり**（0〜4） | 隠し要素。自律型攻撃AIを作った人物の手がかり（§4） | 本編エンド（TRUE） |
| **重大な見逃し** | 悪意ある接続を許可した件数（1夜ごと） | ゲームオーバー |
| **連続ランク D** | 総合評価 D が続いた夜の数 | ゲームオーバー |
| **自分のアカウントの被害** | T4 を許した／T5 の偽フォームにパスワードを入力した回数 | ゲームオーバー |
| **連続残業** | 缶コーヒーで残業した夜が続いた数 | ゲームオーバー |

## 2. 本編エンド（6種類）

上から順に判定し、**最初に条件を満たしたもの**になる。

| # | 名前 | 種類 | 条件 | 内容 |
|---|---|---|---|---|
| END1 | **全責任** | BAD | 最終夜が**重大インシデント** | 顧客情報の流出・全社の業務停止。会社は「夜間担当の過失」と発表し、主人公は懲戒解雇。さらに**損害賠償の請求書**が届く（金額は所持金の全額） |
| END2 | **真夜中の答え合わせ** | TRUE | 最終夜が**完全防衛**、平均ランク **A 以上**、**前任者の手がかり 4つ**（＝最終夜に攻撃元を追跡した） | 自律型攻撃AIを作ったのは、この会社に使い潰されて辞めた**前任の夜勤担当者**だった。主人公は攻撃元を突き止め、前任者とチャットで対話する。夜明けとともに、二人がこの会社をどう終わらせるかが語られる |
| END3 | **引き抜き** | GOOD | 最終夜が**完全防衛**、平均ランク **A 以上**、正しい報告 **5件以上** | 最終夜の対応の記録が業界で噂になり、外資系のセキュリティ会社から誘いが来る。ブラック企業を辞めて転職 |
| END4 | **正社員登用（という名の…）** | NORMAL+ | 最終夜が**完全防衛**、平均ランク **B 以上** | 会社から正社員登用の通知。ただし「管理職扱いのため残業代なし」「夜勤は引き続き担当」。給与明細の額はほぼ同じ。**会社にとっては最高の結末** |
| END5 | **AIに席を奪われる** | NORMAL | 最終夜が完全防衛か一部被害、AIへの依存度 **50% 以上** | 「AIがあれば君はいらない」。会社は SOC-AI の月額契約に切り替え、主人公の契約は終了。最後の夜に AI が丁寧なお別れの挨拶をくれる |
| END6 | **契約更新** | NORMAL | 上のどれにも当てはまらない | 「来月もよろしく」。翌月のシフト表が届く。何も変わらない夜がまた始まる |

- END4 と END5 の両方を満たす場合（完全防衛・B以上・AI依存50%以上）は END4 を優先。

## 3. ゲームオーバー（DAY8〜29）

研修期間（DAY1〜7）にはゲームオーバーなし。DAY30 は本編エンドで決着するため、ゲームオーバーは起きない。

### 3.1 一覧
| # | 名前 | 条件 | 事前の警告 | 内容 |
|---|---|---|---|---|
| GO1 | **契約打ち切り** | 総合評価 **D が3夜連続** | 2夜連続で D になると、翌日の業務メールに上長から「最終警告」 | 「明日から来なくていい」。試用期間満了扱いで契約終了 |
| GO2 | **重大インシデント** | 1夜で**悪意ある接続の許可が3件以上**、または**致命的な脅威**を通した（下表） | なし（その夜の画面に被害の兆候は出る） | 社内システムが攻撃者に乗っ取られ、全社の業務が停止。主人公は懲戒解雇 |
| GO3 | **踏み台** | 自分のアカウントの被害が **2回目** | 1回目: 減給（その夜の日当が ¥1,000）＋パスワード強制変更＋上長から警告 | 主人公の ID から社内が荒らされ、会社は主人公を犯人として警察に突き出す。**パスワードを付箋に書いていた**場合は、その付箋が証拠として押収される（研修のパスワード記録を回収） |
| GO4 | **過労で倒れる** | 残業（缶コーヒー）が **7夜連続** | 5夜連続で、画面がときどきかすむ演出＋同僚（日勤）から心配するメール | 06:30、キーボードに突っ伏したまま朝を迎える。救急搬送され、そのまま退職 |

### 3.2 致命的な脅威（1件でも通すと GO2）
| 脅威 | 致命的になる条件 | 解禁 |
|---|---|---|
| T10 管理者アカウントの乗っ取り | 管理サーバーへの操作要求を許可し、アカウントを停止しないまま夜が終わる | DAY19〜 |
| T11 ランサムウェアの前兆 | 前兆が出てから**ゲーム内30分**以内に感染PCを隔離しない（全社のファイルが暗号化される） | DAY20〜 |
| T14 自律型攻撃AI | 管理系サーバーへの侵入を許す（DAY28〜29） | DAY28〜 |

- 致命的な脅威は、初めて出る夜の業務メール・マニュアルで「**最優先で対応**」と必ず予告する（いきなり終わらせない）。

### 3.3 ゲームオーバー後
- 画面: 社内報の「人事異動のお知らせ」風の1枚絵（「夜間IT運用担当 ○○ 契約終了」）＋原因の説明（どの夜の、どの対応が原因だったか）。
- 選択肢: **［その夜からやり直す］**／［週の初日からやり直す］／［タイトルへ］。
  - やり直すと、所持金・所持品・記録はその夜の開始時点に戻る。
- ゲームオーバーは「エンディング一覧」とは別の **「ゲームオーバー記録」**（GO1〜GO4）に残る。

## 4. 隠し要素: 前任者の手がかり（0〜4）

自律型攻撃AIを作ったのは、前任の夜勤担当者。30日間で少しずつ手がかりが見える（END2 の条件）。

| # | 手がかり | 見つけ方（例） | 解放日 |
|---|---|---|---|
| 1 | 前任者の**付箋**（ワークステーションの裏に残っていた） | サブモニターを導入するとワークステーションの裏が見える | DAY8〜 |
| 2 | 退職者アカウントの悪用（T6）の**接続元**が、ある IP の範囲 | T6 の要求をログで調べる | DAY12〜 |
| 3 | 攻撃支援AIのフィッシングメールに、**社内の人しか知らない言い回し** | T5／AIフィッシングのメール本文 | DAY26〜 |
| 4 | 自律型攻撃AIの通信元が、手がかり2と**同じ IP の範囲** | ログ／相関タイムライン | DAY28〜 |

- 見つけた手がかりは、ワークステーションの「個人フォルダ」に保存すると数えられる。
- 4つ揃えると、DAY30 の最終夜に**「攻撃元を追跡する」**という選択肢が出る。

## 5. エンディング画面
1. **社内報／新聞記事風の1枚絵**（1999年の朝刊・社内報のレイアウト）。
2. **30日間の成績表**: 平均ランク、処理件数、重大な見逃し、所持金、罰金の合計、残業回数、購入した機材・ツール。
3. **エピローグの一文**（所持品・記録で変わる。例: 「サブモニターは次の夜勤担当に払い下げられた」「パスワードの付箋はまだ机に貼ってある」）。
4. **エンディング一覧**（END1〜6。見たものだけ名前が出る。未取得は「？？？」）と**ゲームオーバー記録**（GO1〜4）。
5. タイトル画面へ戻る。一度でもエンディングを見ると、タイトルに「エンディング一覧」が出る。

## 6. 実装メモ
- 30日間の記録 `CareerRecord`（新規）: 各夜の評価・ランク・罰金・残業・AI処理件数・T4/T5 の結果・手がかり。
- 夜の終わりに `GameOverChecker`（新規）で GO1〜GO4 を判定 → 該当すれば評価画面の後にゲームオーバー画面。GO2 の致命的な脅威はシナリオ側から即時に通知する。
- 本編エンドは `EndingResolver`（新規）が §2 の表を上から順に評価。条件の数値は ScriptableObject（`EndingDefinition`）で調整できるようにする。
- やり直し用に、毎夜の開始時点の保存データ（所持金・所持品・記録）を1つ残す。

## 7. 決めること
1. GO1 の判定を「3夜連続 D」にするか「週間評価」にするか
2. GO2 の「1夜で3件」の件数（プレイテストで調整）
3. サブエンド（後で）
